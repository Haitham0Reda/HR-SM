### BLOCKER-1: Test environment files tracked in git with JWT secrets
- **Files:** `.env.test`, `hrsm-license-server/.env.test`, `client/.env`
- **Evidence:** 
  ```bash
  git ls-files | Select-String -Pattern "\.env"
  # Returns: .env.test, client/.env, hrsm-license-server/.env.test
  ```
  - `.env.test:29` contains `JWT_SECRET=test-jwt-secret-key-for-e2e-testing`
  - `client/.env:1` contains `REACT_APP_API_URL=http://localhost:5000/api/v1`
- **Risk:** Test secrets exposed in repository. While these are test-only secrets, they establish a pattern of committing secrets and could be copied to production. Anyone with repo access can forge test tokens.
- **Fix:**
  1. `git rm --cached .env.test hrsm-license-server/.env.test client/.env`
  2. Update `.gitignore` line 15: change `!.env.test` to `# !.env.test` (comment it out)
  3. Add `.env.test` and `client/.env` to `.gitignore` explicitly
  4. Create `.env.test.example` and `client/.env.example` with placeholder values
  5. Update CI/CD to generate `.env.test` from template during test runs
  6. Commit `.gitignore` changes and push
